# Instagram images

A Cloudflare Worker that renders the Instagram feed variant of a photo:

```
/ig/<innerW>x<innerH>/<outerW>x<outerH>/<key>
```

The photo is padded onto the inner frame, then that result is padded onto the
outer frame. Since the inner frame is inset by 100px, the photo always ends up
matted with white on all four sides — matching how these images looked when
they were generated by Thumbor.

## Why this needs a Worker

The rest of the app's images are resized with Cloudflare's URL-based
transformations (`/cdn-cgi/image/…`), but those can't produce this result:

- **They can't be chained.** A `/cdn-cgi/image/` URL isn't fetchable as another
  transform's source — Cloudflare's internal subrequest 404s, surfacing as
  `ERROR 9404: Could not fetch the image`.
- **`fit=pad` alone can't inset.** It always scales the photo until it meets the
  frame on one axis, so there's no way to guarantee a margin on all four sides.
- **The `border` option is Workers-only**, not available in the URL API.

The [Images binding](https://developers.cloudflare.com/images/optimization/binding/)
does support chaining `.transform()` calls, so the framing happens here.

Rails builds these URLs in `Photo#instagram_url` and owns the frame dimensions;
this Worker just applies them. They're consumed by `InstagramJob`, which hands
the URL to the Graph API for Instagram to fetch, and exposed through the
GraphQL API.

## Deploying

```bash
cd cloudflare-instagram-images
npx wrangler deploy
```

Requires an Images Paid plan for the binding. Output is cached at the edge for
a year, keyed on the full path; ActiveStorage keys change when a photo is
replaced, so the URL changes with it.

## Local development

```bash
npx wrangler dev
```

Images binding calls don't incur usage charges in local development.

## Logs

```bash
npx wrangler tail denali-instagram-images
```
